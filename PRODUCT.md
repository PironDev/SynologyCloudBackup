# CloudBackup для Synology — описание продукта

## Что это

Пакет для NAS Synology (DSM 7). Он копирует данные с NAS в облачный диск: копию по расписанию или архивы с историей версий. Сейчас есть два пакета из одного кода:

- **YaDiskBackup** — Яндекс.Диск (REST API или WebDAV);
- **MailRuCloudBackup** — Облако Mail.ru (WebDAV, или приватный API cloud.mail.ru как опция).

## Для кого

Владелец NAS, который хочет внешнюю копию данных в российском облаке. Пользователь знает свой NAS, но не обязан быть администратором облака.

## Проблема

- Встроенный Hyper Backup не работает с Яндекс.Диском и Облаком Mail.ru напрямую.
- Облачные клиенты синхронизируют, а не хранят историю версий.
- Большие файлы упираются в лимиты облака (например, 1 ГБ на файл у Яндекс.Диска без подписки).

## Что делает продукт

1. **Зеркало.** Копирует папки NAS в облако. Меняет только изменённые файлы. Сверяет размер и MD5, если облако отдаёт хеш.
2. **Архив.** Пишет один архив `tar` (с gzip или без) за запуск. Может разбить архив на части заданного размера.
3. **Расписание.** Cron-выражение или однократный запуск в заданную дату.
4. **Ротация.** Удаляет старые архивы: `oldest` — самые старые, `smart` — по одному снимку за день, неделю и месяц.
5. **Шифрование.** Необязательное, AES-256-GCM на NAS до отправки. Пароль не восстанавливается.
6. **Проводник.** Веб-интерфейс: просмотр облака, копирование, перенос, удаление, корзина Яндекса, публичные ссылки.
7. **WebDAV-шлюз.** Облако видно в File Station как сетевой диск.
8. **Дерево папок.** Выбор папок NAS галочками с вложенностью.
9. **Проверка обновлений.** Опционально. Запрос к GitHub Releases, подпись релиза ed25519. Установку делает пользователь через Центр пакетов.
10. **Уведомления DSM.** Через `synonotify` по завершении задания (требует зарегистрированные тексты в пакете).

## Чего продукт не делает

- Не синхронизирует в обе стороны.
- Не копирует настройки системы и установленные приложения (вкладка «Приложение» из Hyper Backup не реализована).
- Не работает как клиент облака на компьютере.
- Не хранит данные облака локально: только настройки, журналы и манифест зеркала.

## Главный сценарий

1. Установить пакет из Центра пакетов (ручная установка `.spk`).
2. Открыть интерфейс DSM или веб-страницу пакета.
3. Указать пароль интерфейса или войти через учётную запись DSM.
4. Добавить аккаунт облака: токен (Яндекс) или пароль внешнего приложения (Mail.ru).
5. Создать задание: папки, исключения, облачная папка, режим, расписание, ротация, шифрование.
6. Проверить сводку: место в облаке, последние запуски, ошибки.

## Модель безопасности (коротко)

- Токены и пароли хранятся зашифрованными AES-256-GCM. Ключ лежит в файле с правами 0600.
- Веб-интерфейс слушает `127.0.0.1` по умолчанию. Доступ извне — через DSM.
- Пароли интерфейса хешируются PBKDF2-SHA256.
- Загрузки проверяются: размер на облаке, MD5 (если есть), mrhash (Mail.ru).
- Отправка отчётов об ошибках выключена по умолчанию и требует согласия.

## Ограничения и риски

- Приватный API Mail.ru не официальный. Он может перестать работать без предупреждения. Включается отдельно и помечен в интерфейсе.
- Проверка с реальными облаками и NAS выполнена не полностью: проверено на фейках и в тестах.
- Лимиты облаков: скорость и число запросов. Есть паузы с нарастанием и учёт `Retry-After`.
- Потеря пароля шифрования означает потерю файлов.
- Потеря ключа подписи обновлений означает, что старые установки не получат обновления.

## Версии и выпуск

- Версия в тегах `vX.Y.Z`. Релиз собирает GitHub Actions: `.github/workflows/release.yml`.
- В релизе: `YaDiskBackup-X.Y.Z.spk`, `MailRuCloudBackup-X.Y.Z.spk`, `SHA256SUMS`, `SHA256SUMS.sig`.

## Открытые вопросы

1. Один пакет для всех облаков вместо двух. Плюсы: один установщик и один интерфейс. Минусы: одно имя приложения DSM, один порт, один набор рисков. Решение не принято.
2. Нужна ли вкладка «Приложение» (копии настроек пакетов DSM). Требует проверки внутренних API DSM.
3. Нужны ли уведомления в DSM в текущем виде. Формат текстов не проверен на NAS.
