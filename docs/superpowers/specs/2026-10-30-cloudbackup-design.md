# CloudBackup для Synology DSM 7 — дизайн

Дата: 2026-10-30. Статус: утверждён пользователем устно («программируй»), реализация идёт по этому документу.

## Цель

Нативные пакеты (SPK) для Synology NAS с DSM 7, которые автоматически выгружают файлы, бэкапы и архивы в облако и показывают облачный диск в File Station. Управление через веб-интерфейс, открывающийся иконкой в меню DSM.

Критерий успеха: установил SPK, подключил аккаунт, создал задание «каждую ночь в 03:00», задание отработало, результат виден в журнале; диск подключён в File Station через WebDAV-шлюз.

## Поставка: два пакета, одно ядро

| Пакет | Имя в DSM | Провайдер | Порты (UI / шлюз) |
|---|---|---|---|
| `YaDiskBackup` | Яндекс.Диск Бэкап | REST API Яндекс.Диска (OAuth-токен) | 8765 / 8766 |
| `MailRuCloudBackup` | Облако Mail.ru Бэкап | WebDAV `webdav.cloud.mail.ru` (пароль внешнего приложения) | 8775 / 8776 |

Оба ставятся независимо и могут работать на одной NAS одновременно. Исходники общие: `cmd/yadisk` и `cmd/mailru` отличаются только `Brand` (название, порты, драйвер хранилища). В каждом пакете можно подключить несколько аккаунтов своего вендора.

Mail.ru: публичного REST API для обычных аккаунтов нет, поддерживается WebDAV; неофициальный API не используется.

## Архитектура

```
cmd/<brand> ──> app.Main(Brand)
                  ├─ store      конфиг (JSON, секреты AES-GCM), аккаунты, задания
                  ├─ engine     Manager (запуски, журнал), mirror, archive, scheduler, Pool провайдеров
                  ├─ provider   интерфейс Provider + yandex (REST) + webdav (клиент) + mailru (обёртка)
                  ├─ gateway    WebDAV-сервер поверх Provider (127.0.0.1) для File Station
                  ├─ web        HTTP API + встроенный UI (embed)
                  └─ auth, cron, httpx, secret
```

### Provider (единый контракт)

`Check, List, Stat, Mkdir (идемпотентно), Upload (Source с повторным Open для ретраев), Download (диапазоны), Delete (рекурсивно), Move, Copy`. Ошибки приводятся к `ErrNotFound / ErrExists / ErrAuth / ErrInsufficientStorage`. Яндекс: токен отправляется только на `cloud-api.yandex.net`, не на хосты загрузки. Загрузка проверяется чтением размера после PUT (в т.ч. при ответе 202).

### Задания

- **mirror** — зеркало папки: выгружает новые и изменённые файлы. Решение «не менялся»: запись в манифесте (размер+mtime) и совпадающий размер на диске; без манифеста — MD5 (если провайдер отдаёт) или `ModTime` на диске ≥ локального. Удалённые локально файлы в облаке не удаляются. Параллельная загрузка (1–16 потоков).
- **archive** — `tar.gz` (быстрое сжатие) с меткой времени, потоково, с разбиением на части `NAME.tar.gz.001…`; одновременно на диске лежит только одна часть. Ротация «хранить N последних» трогает только файлы с именами строго нашего шаблона и только после успешной новой выгрузки. При сбое уже загруженные части снимка удаляются.
- Исключения по умолчанию: `@eaDir`, `#recycle`, `.DS_Store`, `Thumbs.db`.
- Статусы: `success`, `partial` (часть файлов не выгружена), `failed` (в т.ч. нет места / авторизация), `cancelled`.
- Ошибки сети, 429, 5xx — повторы с нарастающей паузой (учитывается `Retry-After`).

### Планировщик

cron из 5 полей (`*`, списки, диапазоны, шаги), локальный часовой пояс NAS. Пропущенные запуски (NAS была выключена) не догоняются. Задание, которое ещё выполняется, повторно не стартует.

### Веб-интерфейс и безопасность

Вход по паролю (задаётся при первом запуске, PBKDF2-SHA256), сессия в HttpOnly SameSite=Strict cookie, для изменяющих запросов обязателен заголовок `X-Requested-With`, блокировка перебора. Секреты в `config.json` зашифрованы AES-256-GCM, ключ в `secret.key` (0600) — защита от случайного просмотра файла, не от человека с доступом к папке пакета. HTTPS — через обратный прокси DSM. Вкладки: Задания, Аккаунты, Журнал, Шлюз File Station, Настройки.

### Шлюз для File Station

WebDAV-сервер на `127.0.0.1`, каждый аккаунт по пути `/<slug>/`. Basic-авторизация отдельным паролем шлюза. Методы: OPTIONS, PROPFIND, GET/HEAD (Range), PUT (потоком; без Content-Length — через временный файл), MKCOL, DELETE, MOVE, COPY, PROPPATCH (заглушка), LOCK/UNLOCK (формальные). File Station подключает его как «WebDAV-сервер». Ограничения File Station для облачных и удалённых источников (нет сжатия, распаковки, предпросмотра) остаются.

### Пакет DSM 7

Один SPK на пакет с бинарниками для x86_64, arm64, armv7 (`arch="noarch"`, скрипт выбирает по `uname -m`). Запуск от пользователя пакета (`run-as: package`); права на чтение общих папок выдаются один раз вручную. Иконка в меню DSM (`ui/config`, тип `url`) и кнопка «Открыть» в Центре пакетов (`adminport`).

## Вне объёма первой версии

Шифрование архивов паролем, двусторонняя синхронизация, удаление в облаке файлов, удалённых локально, восстановление через интерфейс (описано в README командой `cat` + `tar`), уведомления DSM, настройка портов из интерфейса.

## Тестирование

Автотесты без внешней сети: cron, секреты и хранилище, клиент Яндекса против имитатора REST API, WebDAV-клиент против нашего же шлюза, движок (пропуск неизменённых, исключения, архивы по частям, ротация, отмена), веб-API (вход, аккаунты, задания, запуск). Реальные Яндекс.Диск, Mail.ru и DSM в среде разработки недоступны и проверяются пользователем при первой установке.
