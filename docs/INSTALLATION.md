# Установка CloudBackup

## Требования

- Synology DSM 7.
- Учётная запись DSM с правом открыть приложение.
- Доступ к Центру пакетов для ручной установки.
- Доступ к облачным аккаунтам, которые вы подключите.

Пакет содержит сборки для x86_64, arm64 и armv7. Пакет имеет архитектуру `noarch`.

## Установка пакета

1. Скачайте `.spk` из [последнего релиза](https://github.com/PironDev/SynologyCloudBackup/releases/latest).
2. Откройте **Центр пакетов** в DSM.
3. Выберите **Ручная установка**.
4. Выберите скачанный `.spk`.
5. Завершите установку по подсказкам DSM.

Пакет не подписан издателем. DSM может показать предупреждение.

## Первый запуск

1. Откройте CloudBackup из главного меню DSM.
2. Войдите под своей учётной записью DSM.
3. Пройдите мастер знакомства.
4. Добавьте облачный аккаунт.
5. Создайте задание после проверки доступа к исходной папке.

Доступ по умолчанию разрешён администраторам DSM. Чтобы разрешить доступ другому пользователю, настройте `ALLOW_USERS` в файле `service.conf`. Подробности приведены в разделе [Разработка и настройка пакета](DEVELOPMENT.md#параметры-службы).

## Разрешения на папки NAS

Интерактивный файловый менеджер обращается к DSM File Station от имени вошедшего пользователя. DSM применяет права этой учётной записи к просмотру, загрузке, созданию и удалению файлов.

Задания расписания и передача файлов между NAS и облаком работают от системного пользователя пакета. В интерфейсе он показан как `sc-CloudBackup` или похожее имя.

Чтобы фоновое задание прочитало папку:

1. Откройте **Панель управления → Общая папка**.
2. Выберите нужную общую папку.
3. Откройте **Изменить → Разрешения**.
4. Выберите **Системный внутренний пользователь**.
5. Выдайте пользователю пакета право **Чтение**.
6. Добавьте право **Запись**, если задание или передача сохраняет данные в эту папку.
7. Сохраните изменения.

Для личной папки выдайте право только на эту папку и нужные вложенные каталоги. Не выдавайте пакету доступ ко всему `homes`, если это не требуется.

Доступ к родительской общей папке не всегда даёт доступ ко всем вложенным папкам. Проверьте права на конкретную папку. Если DSM использует ACL, примените разрешение к нужным вложенным элементам.

## Подключение Яндекс.Диска

1. Создайте OAuth-приложение в [Яндекс OAuth](https://oauth.yandex.ru/client/new).
2. Укажите Callback URL `https://oauth.yandex.ru/verification_code`.
3. Добавьте права `cloud_api:disk.read`, `cloud_api:disk.write` и `cloud_api:disk.info`.
4. Скопируйте ID приложения.
5. В CloudBackup откройте **Аккаунты → Добавить**.
6. Введите ID приложения и получите токен.
7. Войдите в нужный аккаунт Яндекса и разрешите доступ.
8. Скопируйте токен в CloudBackup и нажмите **Проверить**.

Для каждого аккаунта добавьте отдельный токен. ID приложения можно сохранить в настройках и использовать повторно.

Без подписки Яндекс может ограничивать размер одного файла. Учитывайте этот лимит при настройке размера частей архива.

## Подключение Облака Mail.ru

1. Откройте настройки безопасности Mail.ru.
2. Создайте пароль для внешнего приложения.
3. Разрешите доступ к Облаку.
4. В CloudBackup откройте **Аккаунты → Добавить**.
5. Введите полный адрес почты.
6. Введите пароль для внешнего приложения.
7. Нажмите **Проверить**.

Не вводите обычный пароль от почты.

## Другие провайдеры

Для Amazon S3, Backblaze B2, Google Drive, Dropbox, OneDrive, Box и pCloud следуйте подсказкам формы аккаунта. Для некоторых провайдеров вход выполняется через токен rclone.

## Запасной режим запуска

Если окно DSM не открывается, пакет можно собрать в режиме отдельной вкладки. Этот режим требует отдельной настройки службы. См. [руководство разработчика](DEVELOPMENT.md#локальная-сборка).
