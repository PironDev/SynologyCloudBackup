# Участие в проекте

Перед изменением сначала откройте issue. Опишите проблему или предложите изменение. Дождитесь ответа сопровождающего, если изменение меняет поведение приложения.

## Сообщение об ошибке

Создайте issue по шаблону **Сообщить об ошибке**. Опишите шаги, результат и ожидаемое поведение.

Удалите из отчёта пароли, токены, адреса NAS и имена личных файлов.

## Предложение функции

Создайте issue по шаблону **Предложить улучшение**. Опишите задачу пользователя и ожидаемый результат.

## Pull request

1. Создайте ветку от актуального состояния.
2. Сохраните изменения в приватном сабмодуле, если они меняют код приложения.
3. Опишите проблему и решение в pull request.
4. Укажите проверки, которые вы выполнили.
5. Не добавляйте секреты, реальные журналы или пользовательские данные.

Исходный код находится в приватном сабмодуле `app/`. Без доступа к нему можно изменить только публичные файлы упаковки, документации и CI.

## Локальная проверка

Для изменений в приложении перейдите в `app/` и выполните:

```sh
gofmt -w .
go vet ./...
go test -race ./...
```

Если Go недоступен, укажите это в pull request. Не утверждайте, что проверка прошла, если её не запускали.

Перед отправкой проверьте `git diff` и удалите случайные секреты и персональные данные.
